How it works

Three steps, and you can stop at any of them.

  1. 1

    Run one line

    Paste the command into PowerShell. Nothing is downloaded to your disk and nothing is installed. Windows will ask for administrator rights, because changing these settings genuinely needs them.

  2. 2

    Read the list

    Trim scans your PC and shows you what it would change, labelled by risk. Untick anything you disagree with. Close the window and absolutely nothing has happened.

  3. 3

    Apply, or undo

    Click Apply and it makes the changes you kept. A restore point is taken first, and an undo script lands in C:\ProgramData\Trim\undo that reverses every one of them.

Is it safe?

You are about to pipe a script into an admin shell. Be suspicious.

That is the correct instinct, and it should include being suspicious of this page. Here are three ways to check, ordered by how little you have to take our word for it.

01 Read the source

The script is served as plain text, not as a download. Open it in a browser tab and read all of it before you run anything.

Open the script

02 Check the fingerprint

Every build publishes its SHA256. Running -Version prints the fingerprint of the file actually on your machine.

{{SHA256}}

View /sha256

03 Rebuild it yourself

A hash we publish only proves nobody tampered with the file in transit. So the build is reproducible. Clone the repository, compile it, and you get byte-identical output.

git clone https://github.com/Glexxy/trim
cd trim
.\build.ps1

Same commit, same fingerprint. If it does not match, the published script contains something the source does not, and you should not run it.

Things it will not do, on purpose

  • Touch your camera or microphone. Those, plus screenshots and screen recording, are on a never-touch list enforced at runtime.
  • Go near fan curves, BIOS or overclocking. Out of scope by design.
  • Set up AutoLogon. It writes your password where anything on the box can read it.
  • Remove load-bearing components. Shared frameworks, winget and the Xbox sign-in service are protected and unit-tested.
  • Guess about your hardware. Laptop, desktop, NVIDIA, AMD, Intel, SSD or hard disk — it checks, then skips what does not apply.
  • Phone home. No analytics, no accounts, no network calls except fetching the script itself.

Reversible

The undo is a file, not a promise.

Every registry write goes through one function that records the old value first. At the end of the run — including if it crashes — that ledger is written out as a standalone rollback script.

C:\ProgramData\Trim\undo\undo_<timestamp>.ps1

Three things it cannot reverse, said plainly: removed Store apps (reinstall from the Store), WinUtil’s own changes (use the restore point), and netsh TCP settings (one command, printed in the log).

  • Values that never existed get removed

    Not overwritten with a zero. That single mistake is what makes most “restore” scripts quietly lie about having worked.

  • A restore point first

    Taken before anything is touched, so the whole machine can go back, not just the settings Trim knows about.

  • The round trip is tested

    Apply, roll back, then assert every value returned to its exact previous state and type — including the awkward ones like multi-strings.

Questions

The things people ask before running it.

Is Trim free?

Yes. It is free and open source under the MIT licence. There is no paid tier, no account, and nothing to buy.

Will this break my PC?

It is built specifically to avoid that. Only changes marked SAFE are selected by default, a System Restore point is taken before anything runs, and every registry change is recorded so it can be reversed exactly. It also refuses to touch the categories that actually brick machines: BIOS, fan curves, overclocking, and load-bearing Windows components.

Does it work on Windows 10?

Yes, Windows 10 and Windows 11. It detects which one you are on and skips anything that does not apply to your build.

Do I have to install anything?

No. It runs from PowerShell and leaves no installed program behind. The only files it writes are its own log and the undo script, both under C:\ProgramData\Trim.

Why does it need administrator rights?

Because the settings it changes are machine-wide: scheduled tasks, system services, and registry keys under HKEY_LOCAL_MACHINE. A dry run needs no admin rights at all — you can inspect the entire plan first without granting anything.

Will it improve my FPS?

Honestly: usually a little, sometimes not at all. Removing background telemetry and pointing games at the right GPU has a real effect on some machines and none on a clean, well-specced one. Anyone promising you a guaranteed frame-rate number from registry edits is selling something.

Can I undo it later, not straight away?

Yes. The undo script is a normal file with a timestamp in the name. It stays on disk until you delete it, and it works whenever you run it.

How is this different from WinUtil?

It is not a competitor — it uses WinUtil. Chris Titus Tech’s WinUtil is the debloat engine underneath. Trim wraps it in a specific workflow: a recorded undo path, a dry run you can inspect, hardware detection, and per-change risk labels. If you want a full-featured Windows utility, go and use WinUtil directly.
