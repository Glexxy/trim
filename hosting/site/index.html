You’re piping a script into an elevated shell

That deserves scepticism — including of this page. So here are three ways to check us, in increasing order of how little you have to trust us.

01

Read it

The script is served as plain text, not as a download. Open it in a browser tab and read every line before you run a thing.

open the script →
02

Match it

Every build publishes its SHA256. -Version prints the fingerprint of the file actually running on your machine.

{{SHA256}}
/sha256 →
03

Rebuild it

A hash we publish only proves nobody changed the file in transit. So the build is reproducible — clone the source, compile it, and get identical bytes.

git clone https://github.com/Glexxy/trim
cd trim
.\build.ps1

Same commit, same fingerprint. If it doesn’t match, the published script contains something the source doesn’t — and you should not run it.

The undo isn’t a promise. It’s a file.

Every registry write goes through one function that records the previous value first. At the end of the run — including after a crash — that ledger is written out as a standalone rollback script.

C:\ProgramData\Trim\undo\undo_<timestamp>.ps1
  • A value that didn’t exist before is removed on undo, not overwritten with a zero — the mistake that makes most “restore” scripts quietly lie to you.
  • A restore point is taken before anything runs.
  • The round trip is tested: apply, roll back, then assert every value returned to its exact prior state and type.

Three things it can’t reverse, said plainly rather than buried: removed Store apps (reinstall them from the Store), WinUtil’s own changes (use the restore point), and netsh TCP settings (one command, printed in the log).

What it refuses to do

The restraint is the product. A tweak that wins a frame and costs you a working machine isn’t a trade worth offering.

Touch your camera or microphone

Those, plus screenshots and screen recording, are on a never-touch list checked at runtime. A typo cannot switch off your webcam.

Fan curves, BIOS, overclocking

Out of scope by design. Nothing here can cook hardware.

Set up AutoLogon

It writes your account password where anything on the box can read it back. WinUtil offers it; Trim deliberately doesn’t.

Rip out load-bearing packages

Frameworks other apps link against, winget itself, and the Xbox sign-in component are protected and unit-tested.

Remove Edge

Debloat only. Removal breaks WebView2 dependents, and Windows Update puts it back on most builds anyway.

Guess about your hardware

Laptop, desktop, NVIDIA, AMD, Intel, SSD, spinning disk — every phase checks before it writes, and skips what doesn’t apply.
